# 灵枢·知脉：产品与技术设计

> 版本：0.2（赛题一适配版）
> 目标读者：项目团队、指导教师、评审专家
> 产品定位：面向高校学生、研发人员与知识工作者的 AI 驱动个人知识沉淀与主动学习系统。

## 1. 项目概述

### 1.1 背景与问题

用户越来越多地使用大模型学习、编程和创作，但对话往往停留在一次性问答中：有价值的解释散落在不同平台，概念之间缺少联系，用户难以确认自己是否真正理解，过段时间也容易遗忘。通用笔记产品擅长保存内容，纯 AI 问答产品擅长即时生成答案，但二者通常没有把“AI 对话后的知识沉淀和学习效果”作为完整流程处理。

### 1.2 产品目标

“灵枢·知脉”将用户授权导入的 AI 对话转化为带有来源依据的知识节点和关系，组织为可探索的个人知识图谱；在此基础上提供个人知识检索问答、苏格拉底式追问和间隔复习，帮助用户从“获取答案”转向“形成并巩固自己的理解”。

核心闭环：

```text
对话采集 → 知识抽取 → 人机校验 → 图谱关联 → 知识检索 → 主动回忆 → 间隔复习
```

### 1.3 目标用户与使用场景

| 用户 | 典型场景 | 核心收益 |
| --- | --- | --- |
| 高校学生 | 课程答疑、论文阅读、考前复习 | 把问答整理为知识脉络，定位薄弱概念 |
| 研发人员 | 代码调试、技术选型、阅读文档 | 沉淀问题解决过程和技术决策依据 |
| 知识工作者 | 调研、写作、跨主题学习 | 复用旧知识，发现不同主题间的关联 |

### 1.4 产品原则

1. **来源可追溯**：重要节点、关系和回答都能回到原始对话片段。
2. **AI 生成可校验**：抽取结果先作为候选，允许用户确认、编辑、合并或拒绝。
3. **帮助学习而非代替学习**：默认先给提示和追问，答案由用户主动请求查看。
4. **个人数据可控**：明确展示采集范围、存储位置和删除入口；未经授权不抓取其他应用内容。
5. **解释能力边界**：无证据时说明知识库中没有找到依据，不把模型生成当成事实。

## 2. MVP 范围

### 2.1 必须实现

- 用户登录和个人空间隔离。
- 粘贴对话文本并保存标题、来源和时间；先不做浏览器插件或全平台自动监听。
- 异步抽取概念、摘要、标签、关系和原文证据，展示抽取状态。
- 节点候选的人机校验：接受、编辑、拒绝、与已有节点合并。
- 图谱视图：按主题筛选、搜索、查看节点详情与来源证据。
- 基于个人知识库的 RAG 问答，回答附带引用片段并可跳回来源。
- 苏格拉底式学习会话：按用户回答继续追问，支持查看参考提示。
- 复习卡片、到期队列、掌握程度反馈和可解释的复习调度。
- 基础数据导出与删除能力。

### 2.2 暂不纳入首个版本

- 自动读取浏览器、微信、邮箱或其他平台的用户数据。
- 多人实时协作图谱、知识市场、复杂权限管理。
- 自研基础大模型、GPU 训练和多智能体编排。
- 承诺医学、法律等高风险领域的专业建议。
- 以“全自动准确建图”作为产品承诺；抽取质量必须可校验、可测量。

## 3. 功能设计

### 3.1 对话采集与处理

用户粘贴对话，可选择会话标题、来源平台、主题和隐私级别。保存后创建处理任务，界面显示“排队中 / 抽取中 / 待确认 / 已入图 / 失败可重试”。失败任务保留原文，不重复创建知识节点。

处理步骤：

1. 标准化换行、说话人和时间信息，检测空文本与超长文本。
2. 按轮次和语义边界切分，保留每个片段的原始偏移或稳定片段 ID。
3. 调用模型生成结构化摘要、概念候选、概念定义、关系候选和证据片段引用。
4. 后端验证结构、证据引用和长度；无效结构重试一次，仍失败则进入错误队列。
5. 通过名称与向量相似度召回潜在重复节点，交由用户合并或分别保留。
6. 用户确认后写入节点、关系、来源证据和向量索引。

### 3.2 知识图谱

- 节点类型：概念、方法、问题、结论、项目/作品（MVP 先以“概念”为主，其余用类型字段扩展）。
- 关系类型：属于、解释、依赖、对比、应用于、导致、来源于。关系类型使用受控枚举，避免模型生成大量同义关系。
- 每条边保留置信度、证据片段、生成方式和用户确认状态。
- 可视化用于探索和呈现，不作为唯一数据存储；节点和边的规范化数据保存在数据库。
- 图谱布局优先使用稳定、可交互且支持筛选的图可视化库；小规模个人图谱不需要独立图数据库。

### 3.3 RAG 知识问答

1. 对问题进行向量化和关键词检索。
2. 在当前用户权限范围内召回相关对话片段与知识节点。
3. 可选地扩展一跳相邻节点，补充图谱上下文。
4. 将证据及引用 ID 交给模型生成回答。
5. 后端检查引用 ID 是否属于召回结果；前端提供可点击的原文来源。
6. 没有足够证据时，返回“个人知识库中暂无依据”，可由用户选择启用通用模型回答，并明确标记。

### 3.4 苏格拉底式学习

学习会话围绕用户选定的节点或问题展开。系统先提出一个概念检查问题；根据用户回答判断理解点和遗漏点，再提出一个聚焦追问。避免只用“你确定吗”一类泛化问题。模型输出问题、追问理由、相关知识节点和可选提示；模型不得伪造用户知识库证据。

### 3.5 间隔复习

首版使用可解释的 SM-2 风格调度，而不训练个性化模型。用户选择“忘了 / 有点模糊 / 记得”，系统按反馈更新下次复习时间；保存每次复习记录。卡片问题可由模型生成，但答案必须能追溯到来源或已确认知识节点。

## 4. 总体技术架构

### 4.1 推荐技术栈

| 层 | 选型 | 选择理由 |
| --- | --- | --- |
| Web 前端 | React + TypeScript + Vite | 生态成熟，适合快速开发结构化工作台 |
| UI | Ant Design | 管理型工具组件完整，减少基础控件开发时间 |
| 图谱展示 | Cytoscape.js（或团队熟悉且验证过的同类库） | 支持节点、边、布局、交互与筛选；图谱只是呈现层 |
| 后端 API | Python + FastAPI + Pydantic | Python AI 生态好，类型化请求响应便于联调 |
| 后台任务 | 独立 Worker + PostgreSQL 任务表 | 长耗时模型调用不占用 HTTP 请求；首版避免额外引入消息中间件 |
| 主数据库 | 华为云 RDS（优先 PostgreSQL 兼容方案；若账号指定 GaussDB 则替换） | 统一存储账户、对话、图谱、复习和任务数据 |
| 缓存/任务协调 | Redis（华为云缓存实例） | 任务幂等键、短期状态、限流、热点图谱缓存；不作为唯一数据源 |
| 文件存储 | OBS | 保存用户主动上传的原始附件及导出文件 |
| 大模型 | 账号可用的盘古 / ModelArts 模型推理服务 | 负责抽取、问答和追问；经服务端统一适配调用 |
| 部署 | CodeArts 构建/部署 + ECS + Docker Compose + Nginx | 满足赛题云上部署要求，3 人团队易排错；资源允许时再迁移 CCE |

赛事提供的 AI 开发者空间可作为可选研发资源，用于查阅华为云 AI 开发资源、使用说明和示例；赛题明确必选项是华为云码道 CodeArts 代码智能体，二者在文档和答辩中应区分。

**向量检索能力需在实际账号和区域验证。**优先验证所选 RDS PostgreSQL 版本是否支持所需向量类型、索引和函数；如果支持，使用数据库向量扩展。如果不支持，MVP 可先用“向量落库 + 小规模精确相似度计算”验证闭环，或评估华为云可用的向量检索服务。向量存储通过 `VectorStore` 接口隔离，避免绑定未确认的能力。

       │ RDS            │   │ AI Provider      │   │ OBS             │
       │ 业务数据/任务表 │   │ 盘古/ModelArts   │   │ 附件/导出文件   │

       └───────▲────────┘

CodeArts 负责代码智能体辅助开发、构建流水线和部署编排；应用运行于 ECS，Nginx 提供 TLS 入口并反向代理前端与 API。

### 4.3 华为云服务映射

| 业务能力 | 首选华为云组件 | 使用方式 | 开发前核验 |
| --- | --- | --- | --- |
| 大模型抽取、生成与追问 | 账号可用的盘古大模型 / ModelArts 推理服务 | 后端 Provider 适配器调用 | 区域、模型版本、调用权限、限流、计费、结构化输出能力 |
| 应用部署 | ECS | Docker Compose 部署 Web/API/Worker/Nginx | 配额、网络、镜像拉取、带宽与安全组 |
| 结构化数据 | 华为云 RDS（或账号指定的 GaussDB） | 保存用户、对话、节点、关系和复习数据 | 引擎版本、连接方式、备份策略、向量能力 |
| 缓存与任务协调 | Redis | 任务幂等、状态短存、限流和热点缓存 | 私网访问、密码、持久化策略、过期时间 |
| 原文件存储 | OBS | 服务端签名上传或 API 代理上传，按用户隔离对象路径 | 桶区域、访问策略、生命周期与流量费用 |
| TLS 域名 | 可用的云证书/域名服务 | Nginx 或网关绑定 HTTPS | 比赛是否需要公网域名及备案要求 |

不在首版强行加入 Kafka、专用图数据库、GPU 训练。CodeArts、RDS、Redis 和 ECS/CCE 的最终规格以账号控制台和赛题资源发放为准；云资源规格和价格以当期报价为准，文档不预设免费额度。

### 4.4 CodeArts 智能体与 Skills 工作流

CodeArts 是本项目从想法到上线的开发基础设施，按以下方式留存可审计证据：

1. **需求理解**：将本设计文档拆为前端页面、API、数据表和 AI Provider 任务，由 CodeArts 代码智能体生成任务清单和初始代码骨架。
2. **代码生成**：让智能体根据 OpenAPI 契约生成 FastAPI 路由、Pydantic 模型、数据库迁移和 React 请求层；人工审查权限、幂等和数据删除逻辑。
3. **云服务开通**：通过已有或自定义 Skills 读取区域、规格、网络和安全组参数，辅助开通 RDS、Redis、OBS 等资源；实际开通前由队员复核费用和最小权限。
4. **问题修复**：将 CI 构建失败、依赖冲突、连接超时和模型响应结构错误作为上下文交给智能体，形成“错误→定位→补丁→测试”的记录。
5. **构建部署**：CodeArts 构建镜像，执行测试和健康检查，再部署到 ECS；资源允许时使用 CCE 扩展副本。每次发布保留版本号和回滚点。
6. **开源交付**：导出脱敏后的 Skill 说明、部署脚本、接口文档和使用文档，放入 Gitee/GitHub 仓库，确保其他团队可按文档复现。

推荐保留的 Skill 最小集合：`provision-rds`、`provision-redis`、`deploy-web-api`、`run-migrations`、`smoke-test`。Skill 不得保存明文 AK/SK、数据库密码或用户原文。

## 5. 后端模块与 API 草案

### 5.1 模块边界

- `auth`：注册/登录、令牌、用户隔离。
- `conversation`：原文、来源、分段及删除。
- `extraction`：任务创建、Worker、模型输出验证、重试。
- `knowledge`：节点、关系、证据、去重与用户校验。
- `retrieval`：关键词与向量召回、RAG 上下文组织、引用校验。
- `learning`：追问会话、复习卡片、调度和学习事件。
- `providers`：`LLMProvider`、`EmbeddingProvider`、`VectorStore`、`ObjectStorage`、`CacheStore` 适配层。

### 5.2 API 草案

| 方法与路径 | 说明 |
| --- | --- |
| `POST /api/v1/auth/register` | 注册演示账户 |
| `POST /api/v1/auth/login` | 登录并获取访问令牌 |
| `POST /api/v1/conversations` | 创建对话并提交抽取任务 |
| `GET /api/v1/conversations` | 分页读取当前用户对话 |
| `GET /api/v1/jobs/{job_id}` | 查询异步处理状态及错误信息 |
| `GET /api/v1/knowledge/graph` | 按筛选条件返回节点和关系 |
| `PATCH /api/v1/knowledge/nodes/{id}` | 编辑/确认节点 |
| `POST /api/v1/knowledge/merge` | 合并重复节点 |
| `POST /api/v1/knowledge/query` | RAG 问答，返回答案和引用 |
| `POST /api/v1/learning/sessions` | 为选定节点创建主动学习会话 |
| `POST /api/v1/learning/sessions/{id}/answers` | 提交回答并请求下一轮追问/反馈 |
| `GET /api/v1/reviews/due` | 读取到期复习队列 |
| `POST /api/v1/reviews/{card_id}/grade` | 提交记忆反馈并更新复习时间 |
| `DELETE /api/v1/conversations/{id}` | 删除对话及关联证据/节点处理策略 |

统一响应包含 `request_id`；错误响应包含稳定错误码、用户可读信息和可排查日志 ID，不向客户端返回密钥或堆栈。

## 6. 数据模型草案

所有业务记录带 `user_id` 和创建/更新时间；查询必须在服务端按当前用户过滤，不能信任客户端提交的用户 ID。

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `users` | `id, email, password_hash, created_at` | 账户；口令仅保存强哈希 |
| `conversations` | `id, user_id, title, source, raw_text, status, created_at` | 用户提交的原始对话 |
| `conversation_chunks` | `id, conversation_id, sequence, content, token_count` | 分段原文，引用定位的基础 |
| `knowledge_nodes` | `id, user_id, canonical_name, type, description, status` | 规范化知识节点 |
| `knowledge_edges` | `id, user_id, source_id, target_id, relation_type, confidence, status` | 节点关系 |
| `evidence` | `id, user_id, chunk_id, node_id/edge_id, quote, offsets` | 节点/关系来源证据 |
| `embeddings` | `id, user_id, object_type, object_id, model, dimension, vector` | 向量及模型版本元数据；物理实现由 VectorStore 决定 |
| `jobs` | `id, user_id, type, status, attempts, error_code, payload` | 异步任务与幂等处理 |
| `review_cards` | `id, user_id, node_id, question, answer, due_at, interval, ease` | 复习内容及调度状态 |
| `review_events` | `id, card_id, grade, reviewed_at, next_due_at` | 复习历史与评估依据 |
| `learning_sessions` | `id, user_id, node_ids, status, created_at` | 主动学习会话 |
| `learning_turns` | `id, session_id, role, content, evidence_ids, created_at` | 学习对话与引用依据 |

删除对话时需定义清楚：原文、分段、证据和仅由该对话产生且未被其他来源支持的节点是否级联删除。推荐 MVP 标记来源被删除，并保留有其他有效来源的节点；提供删除预览，避免误删共享知识。

## 7. AI 设计与质量控制

### 7.1 模型适配

后端不直接在业务代码里硬编码某个厂商 SDK。定义统一接口：

```text
LLMProvider.generate_structured(schema, input, timeout)
LLMProvider.generate_answer(messages, timeout)
EmbeddingProvider.embed(texts, model_version)
```

按账号实际可用的大模型端点实现华为云 Provider；模型名称、区域、端点和超时从服务端环境变量读取。模型响应先经过 Pydantic/JSON Schema 验证，不合法则有限重试并记录失败任务。

### 7.2 抽取输出契约

抽取模型输出受控 JSON，至少包含：

```json
{
  "summary": "对话摘要",
  "nodes": [{"name": "概念名称", "type": "concept", "definition": "简明解释", "evidence_chunk_ids": ["chunk-id"]}],
  "edges": [{"source_name": "概念 A", "target_name": "概念 B", "type": "explains", "evidence_chunk_ids": ["chunk-id"]}],
  "open_questions": ["尚未解决的问题"]
}
```

模型只能引用输入中存在的 `chunk_id`；证据为空或无法匹配时，后端拒绝将该项标为已验证。去重采用“规范化名称 + 类型 + 相似度召回 + 用户确认”，不能仅凭一次模型判断自动覆盖旧节点。

### 7.3 RAG 防幻觉与隐私

- 每次回答记录检索到的 `evidence_id` 和模型版本。
- 回答引用只能来自本次检索结果；后端校验引用对应当前用户数据。
- Prompt 明确区分“用户笔记事实”和“通用模型补充”，通用补充单独标注。
- 发送给模型的数据遵循最小必要原则；提供对话删除和数据清除流程。
- 不把模型 API 密钥放入前端、不提交到代码仓库、不写入日志。
- 对输入做长度限制、提示词注入防护和敏感信息提醒；模型不得执行外部工具或访问其他用户数据。

## 8. 安全、隐私与可靠性

- HTTPS 访问；生产环境口令使用 Argon2id 或 bcrypt 强哈希。
- JWT/会话密钥与云服务凭证存放于服务端环境或云侧密钥管理能力，禁止写入前端构建产物。
- 数据库使用 TLS 和最小权限账户；OBS 桶默认私有，临时访问链接设置短有效期。
- 每个查询、缓存键、对象路径和后台任务都绑定 `user_id`，增加跨用户隔离测试。
- 上传文件校验类型、大小和内容；限制抽取文本长度，避免异常成本。
- 日志记录 `request_id`、任务状态和耗时，不记录原文全文、令牌和敏感答案。
- 数据库定期备份；任务具备幂等键、有限重试、超时和失败可重跑能力。
- 页面展示删除、模型处理中和任务失败状态；模型或云服务不可用时，保留原始对话并允许稍后重试。

## 9. 评测方案与参赛指标

所有指标先在自建小型测试集上测量，再报告真实结果；下表目标是设计门槛，不得在未测试时作为已实现成绩宣传。

| 维度 | 指标 | 初始验收目标/方法 |
| --- | --- | --- |
| 抽取质量 | 节点 Precision / Recall、关系准确率、证据有效率 | 构建不少于 100 段人工标注样本；先追求证据有效率 ≥ 95%，再迭代抽取质量 |
| 去重质量 | 重复节点识别 Precision、误合并率 | 人工构造同义/近义/不同概念样本；误合并作为高风险错误单独统计 |
| RAG 质量 | Recall@5、引用正确率、答案有据率 | 至少 50 个带标准来源的问题；无命中时检查是否能拒答 |
| 主动学习 | 追问相关性、用户能否回答、提示是否有帮助 | 小范围用户测试和人工双人评分，不把模型自评分当作唯一依据 |
| 学习成效 | 复习完成率、7 日后回忆正确率、主观负担 | 与仅保存笔记的流程做小规模前后测，避免夸大因果结论 |
| 工程质量 | API P95、任务失败率、恢复时间 | 记录测试环境、样本量、模型版本和日期；模型耗时单独统计 |
| 隐私安全 | 越权读取、密钥泄露、删除残留 | 自动化跨用户访问和删除链路测试，敏感信息扫描代码仓库 |

比赛演示准备一套可重复数据：至少 3 段跨主题对话、人工核对过的节点关系、10 个已知答案的问题和 5 张复习卡。演示时展示来源引用与一次抽取纠错，体现系统不是只生成一张“看起来像图谱”的图。

## 10. 部署与开发环境

### 10.1 环境划分

- 本地开发：Docker Compose 启动前端、FastAPI、Worker、PostgreSQL 和 Redis；模型服务通过开发环境凭证调用，使用合成数据。
- 云端演示：CodeArts 构建/部署应用；ECS 运行前端、FastAPI、Worker 和 Nginx；RDS 托管业务数据；Redis 提供缓存/任务协调；OBS 存放附件；模型调用端点配置在后端环境。
- 生产化方向：根据并发和可用性要求评估负载均衡、容器服务、消息服务、备份和监控，MVP 阶段不提前承担这些复杂度。

### 10.2 CodeArts 构建与部署流水线

```text
代码提交 → CodeArts 代码检查 → 单元/API 测试 → 构建镜像
       → 推送镜像仓库 → 执行数据库迁移 → 健康检查
       → 部署 ECS/CCE → 冒烟测试 → 发布或自动回滚
```

流水线必须区分迁移失败、模型端点不可用、RDS/Redis 连接失败和前端构建失败；禁止“构建成功但服务未检查”即宣布部署完成。每次演示发布记录提交号、镜像标签、数据库迁移版本和环境变量版本。

### 10.3 CI 与配置

- 前端：lint、TypeScript 检查、构建。
- 后端：格式/静态检查、单元测试、API 集成测试、数据库迁移检查。
- 发布：构建镜像、部署演示环境、健康检查、回滚到上一个镜像版本。
- 配置使用 `.env.example` 提供变量名，不提交真实 `.env`；数据库迁移使用 Alembic。

关键配置项示例（只列变量名，不放真实值）：

```text
APP_ENV
DATABASE_URL
JWT_SECRET
HUAWEI_LLM_ENDPOINT
HUAWEI_LLM_MODEL
HUAWEI_LLM_API_KEY
OBS_ENDPOINT
OBS_BUCKET
OBS_ACCESS_KEY
OBS_SECRET_KEY
```

## 11. 项目组织与三人分工

三人共同负责产品验收、接口评审和演示；分工按主责划分，避免模块无人集成。

| 角色 | 主责 | 交付物 |
| --- | --- | --- |
| A：前端与体验 | 页面信息架构、图谱、对话采集、检索与复习界面、前端测试 | 可演示 Web 客户端、组件与交互状态 |
| B：后端与数据 | FastAPI 模块、RDS/Redis 模型与迁移、认证、任务状态、部署自动化 | API、数据库迁移、Docker 部署与接口文档 |
| C：AI 与评测 | 华为云模型 Provider、抽取/去重/RAG/追问/复习逻辑、评测集和提示词 | 可替换的模型接入层、评测报告、演示样例 |

集成约定：先确定 OpenAPI 契约和统一错误格式；每日合并到主分支；云资源凭证由一人管理并通过安全渠道配置，不发在群聊、文档或仓库里；每周完整走通一次从采集到复习的端到端流程。

## 12. 里程碑与验收

| 阶段 | 目标 | 验收标准 |
| --- | --- | --- |
| 0. 资源验证 | 确认区域、模型调用、RDS、Redis、OBS、ECS 权限与网络 | 能从本地安全调用模型；云端数据库、缓存和 OBS 连通；记录费用与限额 |

| 4. 比赛呈现 | 架构图、产品演示、技术与商业论证 | 5 分钟内完成端到端故事，不依赖临场手工改库 |

## 13. 商业落地假设

- **个人订阅**：基础知识库免费，高级检索、更多模型额度、跨设备同步或导出能力订阅。
- **高校/实验室版**：课程/实验室空间、组织知识沉淀、教师配置课程材料与学习复盘。
- **企业研发版**：私有知识库、技术方案与故障复盘沉淀、权限与审计能力。

上述为待验证的商业假设，不代表已验证收入。早期验证优先观察：用户是否持续导入对话、是否接受 AI 抽取纠错、是否愿意每周复习、知识检索是否减少重复提问。需评估模型推理成本、个人数据敏感性、学校采购周期和已有笔记/AI 产品的替代关系。

## 14. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 模型端点/区域不可用或限流 | 演示链路中断 | 阶段 0 先验证；实现 Provider 抽象、超时与有限重试；准备明确标注的离线演示数据 |
| 抽取错误和重复节点 | 图谱失真 | 人机确认、证据绑定、相似节点召回；追踪误合并率 |
| RAG 生成无依据回答 | 用户被误导 | 强制引用、引用 ID 后验校验、低证据时拒答 |
| 数据泄露或越权 | 严重信任损失 | 全链路 `user_id` 授权、私有 OBS、服务端密钥、隔离测试和删除审计 |
| 云资源费用不可控 | 超预算 | 设定文本长度和调用频次限制，使用缓存与测试配额，按控制台账单监控 |
| 范围膨胀、集成延期 | 核心闭环无法完成 | 首版不做插件、训练、多租户协作或微服务；先交付纵向闭环 |

## 15. 开发前待确认清单

以下事项需要在华为云控制台或服务文档中逐项核验后，固化到实施方案：

1. 账号所在区域、项目/子账号权限和可用额度。
2. 盘古或 ModelArts 可调用的具体模型、API 形式、认证方式、限流和计费。
3. RDS（或账号指定 GaussDB）的引擎版本，以及向量类型/索引能力是否满足向量检索方案。
4. OBS、ECS 的区域、网络连通、预算和部署权限。
5. 比赛对云端部署、数据安全、现场网络和华为云产品使用证明的要求。

本设计不假设上述服务已全部开通；阶段 0 核验结果决定最终选型。
